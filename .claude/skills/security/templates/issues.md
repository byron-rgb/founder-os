# Security issues

Every security finding, open and fixed. One row per issue. Never delete a row: mark it fixed or accepted instead, so the history stays.

- **Severity:** high (fix this week), medium (fix this month), low (when you get a chance).
- **Status:** open, fixed, accepted (owner chose not to fix, reason in Notes).
- **Source:** the check that found it (e.g. "Email spoofing check"), or "owner" if they told us.
- **Area:** a number from the report (1 to 13).

---

Rules for updating:
- New finding: next number, add to Open with today's date.
- Same finding again: don't add a new row. Update the Notes on the open one ("still there {{DATE}}").
- Gone at the next check, or the owner fixed it with you: move it to Fixed with today's date.
- Never write a password, key or code here. Write `[removed]`.
